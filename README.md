# SNIProxy 管理面板 + AdGuard Home 融合版

通过网页管理 SNIProxy 域名转发、按客户端分流的 DNS 和全局兜底 DNS。安装器默认同时安装 AdGuard Home，登录 SNIProxy 后即可从同一个 HTTPS 面板进入 AdGuard Home，不用另设密码或开 SSH 隧道。

## 一键安装 / 升级

**支持 Debian / Ubuntu（systemd，amd64 或 arm64）。** 在服务器上以 **root** 执行。不需要 Git、GitHub 登录或手动上传国家数据库。

```bash
f=$(mktemp) && curl -fLsS 'https://raw.githubusercontent.com/zwgwl258/sniproxy/24a9ff0bcf4d0b3b14037559589ecd4fa9bf9e2b/install_cmd.sh' -o "$f" && bash "$f"
```

此命令固定到已验证的安装版本，不受仓库首页文档更新影响。安装器会校验下载的归档。
[查看本版 Linux 部署、Debian 11 构建、客户端监控与运行期切换测试](https://github.com/zwgwl258/sniproxy/actions/runs/42014023475)。

- **全新安装**：仅在配置文件不存在时写入默认模板，预置 12 个域名组（324 条规则），全局兜底 DNS 留空，使用系统 DNS。成功后终端会显示面板地址、用户名 `admin` 和初始密码。首次登录必须修改密码（12–128 个字符），然后用新密码重新登录。不要公开安装输出中的密码。
- **覆盖升级**：运行同一条命令即可保留域名、DNS 规则和已有面板密码，服务可能短暂重启。平时可以从「修改面板密码」更换密码。
- **旧服务**：若旧的 `sniproxy.service` 正在运行，安装器不会停掉它，也不会启动新版代理抢占端口。已独立初始化的 AdGuard Home 不会被重置或自动迁移到统一登录。

### Debian 11：Autoconf 2.69

直接使用上面同一条安装命令，不需要另用旧版安装包。安装器所用源码已通过 Debian 11 构建验证。

## 使用面板

默认访问 `https://服务器公网IP:9443/`。安装器打印的地址可能是内网 IP；远程访问时请使用实际可达地址，并只允许管理员来源访问 TCP 9443。默认是自签名证书；应核对安装时显示的指纹，或用与访问地址匹配的可信证书。具体参数见[部署说明](deploy/README.md)。

| 功能 | 怎么用 |
| --- | --- |
| 域名转发 | 全部可管理域名每行一条。直接增、改、删，点「保存域名列表」统一应用。支持批量粘贴域名或 `.*example\.com$ *` 形式的规则。 |
| 客户端 DNS 分流 | 填来源 IP、CIDR，或搜索选择国家／地区，再填 DNS IP。已添加规则可搜索、翻页、修改和删除。 |
| 全局兜底 DNS | 每行一个 DNS IP，不设固定条数上限。未命中分流规则时直接使用；客户端专用组未返回可用地址时也会尝试。清空并保存后恢复默认 DNS。 |
| 高级配置 | 修改监听地址、默认 DNS 或自定义转发表。可校验并应用、查看日志、重启及恢复上一版配置。 |
| AdGuard Home | 点击标题旁的「AdGuard Home 管理」进入同一 HTTPS 地址的 `/adguard/`。融合模式不用填写单独的后台地址。 |
| 客户端 IP 监控 | 点击标题旁的「客户端 IP 监控」，查看当前已建立连接的来源 IP 和连接数；支持搜索、分页，以及「全部 IP／排除白名单 IP」两种显示方式。可逐个加白、移除，或手动添加 IPv4／IPv6。白名单仅用于显示筛选，不是防火墙，不阻止其他 IP 连接；修改白名单不重启代理。 |
| 域名分组流量 | 展开首页「域名分组流量监控」，查看每组上传／下载 MB/s、累计 MB 和占比。按生产代理实际命中的原版规则归组，支持复杂正则；命名表及不可归组的规则单列「其他」。展开时约每 5 秒局部更新，不刷新正在编辑的配置。 |

客户端监控按生产 SNIProxy 主进程及实际监听端口统计，不把上游连接或测速进程算作客户端。页面手动刷新，无两分钟自动刷新，也不保存历史访问记录。白名单保存于 `/etc/sniproxy-managed/client-whitelist.json`，升级保留。

分组流量按客户端视角统计：上传为发往上游的数据，下载为发往客户端的数据，每个方向只计一次。MB = 1,000,000 字节，速度为约 5 秒平均值。累计从本次代理启动开始，重启清零，不补算升级前流量；不包含 IP/TCP 包头、测速进程或其他程序，因此不会等于服务器网卡的上／下行总流量。计数在内存中更新，每约 5 秒写入一次 `/run` 快照，不逐包写日志。

客户端来源以代理实际看到的 TCP 来源 IP 为准。匹配优先级：**IP／网段 → 国家／地区 → 全局兜底 DNS（未设置则用默认 DNS）**。安装器自动下载并校验 [DB-IP Country Lite](https://db-ip.com/db/download/ip-to-country-lite)。健康的客户端专用 DNS 不受全局分组熔断影响；它们全部 DNS 探测失败后才进入兜底。

### 稳定优先的 DNS 分组与实时熔断

- 域名列表用**空行分组**，同组使用同一兜底 DNS。全部可识别的简单域名规则参与测速；任意复杂正则不能自动猜出测试主机名，仍保留原规则，不承诺其参与分组测速。
- **每 30 分钟综合测速**全部可测试域名和候选 DNS，比较 HTTPS 成功覆盖率、首字节和 DNS 耗时，形成备用排序。每台 DNS 复用一个独立测试代理，最多 4 台 DNS × 每台 4 个域名并发；DNS 未返回地址时跳过无效 HTTPS 测试。实际耗时取决于域名、DNS 数量和超时，面板显示上轮耗时，不保证固定几分钟完成。
- **当前 DNS 没有确认故障就不换**。定时测速不会因另一台更快而替换首选，也不会仅因一次合成测试失败而换 DNS。
- 实时监测生产代理的兜底查询及 TCP 建连结果，约每 **15 秒**检查近 **60 秒**样本。至少 30 次建连结果且失败率 ≥50%，或等待建连 ≥100 个，或至少 30 次建连成功且上游重置比例 ≥50%，连续两次检查满足后进入复核。客户端接收错误不计为上游失败；未完成的受监测建连最多等待 10 秒，避免长时间积压。
- 复核实际出错的主机名（最多 3 个），对当前 DNS 和至多 3 个备用各复测两次。当前线路复测通过则保持并告警；只有当前未连续通过、备用连续全部通过时，才按备用排序**整组切换**。无可靠备用就告警并保留当前，不盲目轮换。复测后台限流，每组至多两分钟启动一次复核。
- 故障 DNS 冷却 **10 分钟**，到期后仅可作为下次故障复核候选，不自动抢回首选。
- API 返回 401／403／404／405 不直接判为 TCP／TLS 断线；备用若仍解析到当前复测失败的上游 IP，也不当作有效备用。
- **故障切换不重启 SNIProxy**：运行期路由文件热更新，新连接采用新 DNS，已建立的连接保持原路由。旧连接无法迁移，所以切换期间不能保证所有连接出口瞬间一致。代理解析本身没有跨查询结果缓存；既有连接不因换 DNS 被清理。
- 面板按组显示当前／备用 DNS、近一分钟 TCP 建连成功率、待连接数、平均建连耗时、异常上游、冷却节点及最近切换原因。非阻塞监测为尽力采样，繁忙时可能丢样；TCP 连通和 HTTPS 首页成功**不等于业务登录或地域解锁成功**。
- 监测服务不可用时面板显示心跳失效；已发布的运行期首选保留，不因监测进程故障而追快切换，但此时不能自动熔断。选择持久化于 `/etc/sniproxy-managed/dns-runtime.json`，不覆盖用户域名、DNS 或密码配置。

尚无分组报告时，兜底沿用每 5 分钟的 example.com DNS 探测和普通查询回退策略；查询成功并不保证网站可达。未配置兜底 DNS 时使用系统／默认解析。已有客户端专用 DNS 的完整业务故障切换不属于本次全局兜底分组熔断。

## 默认端口和 AdGuard Home 规则

| 组件 | 全新安装默认值 |
| --- | --- |
| SNIProxy HTTPS 管理面板 | TCP `9443` |
| SNIProxy 流量监听 | 新安装默认 `0.0.0.0:80`（HTTP）和 `0.0.0.0:443`（TLS）；防火墙仅放行可信客户端 |
| AdGuard Home Web 后台 | 本机 `127.0.0.1:3000`，由面板转发 |
| AdGuard Home DNS | 新安装默认监听服务器网卡 IPv4 的 TCP/UDP 53；防火墙仅放行可信客户端 |

远端客户端如果要连接代理，请先在「高级配置」中设置实际监听地址和转发表，再按需放行端口。不要开放公网 AdGuard Home 后台或把 DNS 暴露为公共解析器。

融合版安装会为 AdGuard Home 写入自定义过滤规则：

```text
|*^$dnsrewrite=NOERROR;A;你的公网IPv4
```

默认自动检测公网出口 IPv4。如果 NAT 或负载均衡使出口 IP 与客户端实际使用的代理地址不同，可把安装命令最后的 `bash "$f"` 改为 `ADGUARD_PUBLIC_IP=实际公网IPv4 bash "$f"`。脚本不会覆盖指向其他 IP 的现有同类重写。新装时 **AdGuard DNS filter** 和 **AdAway Default Blocklist** 默认关闭，升级不覆盖已有黑名单状态。

**这是全域名 A 记录重写。不要把这一实例作为 SNIProxy 解析真实后端的上游 DNS，否则可能把流量指回代理自身。** 安装器不会替你切换现有 DNS 规则。

## 常用检查

```bash
systemctl is-active sniproxy-panel.service sniproxy-managed.service sniproxy-adguard.service sniproxy-dns-health.service
journalctl -u sniproxy-panel.service -n 50 --no-pager
```

配置位于 `/etc/sniproxy-managed/`，集成的 AdGuard Home 数据位于 `/opt/sniproxy-adguard/`。升级或迁移前建议备份这两个目录。
